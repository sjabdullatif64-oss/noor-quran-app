---
name: Disable a Capacitor plugin in the native build
description: Why removing a Capacitor plugin from includePlugins/package.json is not enough; the native Android build has multiple references that must be cleared.
---

When a Capacitor plugin is no longer used (e.g., because the web feature is gated off), removing it from `includePlugins` and `package.json` is not enough. The native Android build also references it in:

- `android/settings.gradle` (the `include` and `project().projectDir` lines)
- `android/app/build.gradle` (the `implementation project(...)` line)
- `android/app/src/main/assets/capacitor.plugins.json` (regenerated by `npx cap sync`, but can be stale if not synced)
- `MainActivity.java` (the Java import and the `registerPlugin(...)` call)

If any of these references remain after the plugin is removed from the native modules, the release build fails with errors such as:

```
error: package com.getcapacitor.community... does not exist
error: cannot find symbol
```

**Why:** The Android build uses explicit Gradle includes and explicit plugin registration in `MainActivity`. Capacitor's auto-discovery via `capacitor.plugins.json` is bypassed by the explicit `registerPlugin()` calls, so stale imports cause a compile failure even if the web layer no longer reaches the plugin.

**How to apply:** When disabling a Capacitor feature, grep for the plugin's npm package name and Java class name across `android/` and `capacitor.config.ts`, then remove every match. Run `npx cap sync android` afterwards and verify the build.
